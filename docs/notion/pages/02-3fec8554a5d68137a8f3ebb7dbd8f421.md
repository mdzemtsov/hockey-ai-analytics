# ⚙️ 02 — Technical pipeline, data contracts & QA

[Notion source](https://app.notion.com/p/3fec8554a5d68137a8f3ebb7dbd8f421?pvs=204) · [Index](../README.md)

> Historical Notion snapshot. Design targets and older status claims are not current implementation guarantees. See [current baseline](../../BASELINE_QA.md). Child-identifying names, team name and individual profile details have been generalized for public sharing.

User workflow: put original videos in Drive, write 'Вперёд. Новое видео' in Hockey Life chat; assistant orchestrates processing and saves finished reviews in Drive. No separate user-facing application. An execution runtime for video processing is nevertheless necessary; ChatGPT chat alone cannot be assumed to process arbitrary full games and render MP4 unattended.

## Inputs and manifest

Game ID, date, team, opponent, rink, 8U/10U, format (full/half ice), player jersey number and team color, camera sources, file links, permission/license status, timezone, game-clock information, roster/bench orientation optional. Persist profile separate from game overrides. Never embed private player metadata into public outputs.

## Pipeline stages and interfaces

1. Discovery: list only new files in authorized Drive folder; stable file IDs, checksum, upload-complete signal, deduplication; prevent repeated runs.
2. Ingest: download permitted files, inspect codec/resolution/frame rate/timebase, validate duration and corruption; original immutable.
3. Multi-camera sync: use clock, whistle/audio peaks, puck drop and manually validated anchor events; per-camera offsets, drift corrections; fallback to single camera.
4. Rink calibration: detect boards, circles/lines; camera lens correction, homography for planar ice. Track camera pan/zoom; re-estimate transform and uncertainty. Never interpret screen pixels as absolute rink coordinates without calibration.
5. Detection: candidate players, officials, goalies and puck via object detection; fine-tune for hockey footage. Puck detection is high-risk due to blur, occlusion, small size. Bench and boards create false positives.
6. Multi-object tracking: ByteTrack or BoT-SORT; jersey color, number OCR, spatial/temporal consistency, roster references; player identity confidence. Track IDs are not player IDs. Re-identify after occlusion and substitutions; manual confirmation for ambiguous the selected player.
7. Event proposals: shifts, puck touches when visible, passes, turnovers, shots, transitions, positioning windows. Avoid declaring possession from proximity alone. Maintain event provenance and missing observations.
8. Game-state representation: rink-space coordinates, attacking direction, teammates/opponents, puck certainty, zones, trajectories, pressure and options; calibrated measurement error.
9. Coaching reasoning: explicit rule/knowledge retrieval + multimodal model generates candidate explanation; verify each factual claim against timecoded observations; age-specific constraints; uncertainty gates and human review.
10. Event ranking: coverage, coaching usefulness, confidence, skill diversity, nonredundancy and balanced praise/correction. Default 10, never pad with fictional events.
11. Telestration: real footage, highlight the selected player, freeze-frame, arrows and lanes in screen space projected from rink coordinates; use static 2D tactics diagram if camera geometry unreliable. Do not fabricate photorealistic alternate play.
12. Narration: short Russian script, neutral encouraging tone, TTS (e.g. ElevenLabs); caption generation and voice/audio mixing.
13. Render: FFmpeg/OpenCV/Remotion pipeline to MP4 with source clips, timestamps, slow-motion, overlay and narration; separate full source and annotated highlights.
14. QA: detect black frames, audio clipping, wrong player circles, arrows drifting off rink, unsourced statements, inappropriate criticism, copyright/consent issues; parent approval on first releases.
15. Publish: write outputs to restricted Drive folders, persist JSON/CSV event manifest and report; link artifacts back to Notion project.

## Tools and limitations

OpenCV (geometry and overlays); YOLO-type detector (candidate objects, not tactics); ByteTrack/BoT-SORT (temporal IDs, not true identities); OCR (jersey text often unreadable); Python and FFmpeg (media processing); Remotion optional for polished overlays; LLM/VLM (reasoning, not ground truth); TTS (narration); Drive connector (files); Notion (spec). Deployment/runtime must be proven rather than assumed.

## Data contract per event

event\_id; game\_id; source\_file\_id; camera\_id; start\_ms; decision\_ms; end\_ms; player\_track\_id; identity\_confidence; puck\_confidence; observation; alternative\_options; decision\_quality; execution\_quality; outcome; evidence\_frames; coaching\_rule\_id; age\_band; confidence; narration\_ru; overlays; review\_status.

## Quality gates — proposed targets, not achieved

- Player identity precision >= 98% on events actually narrated; uncertain clips withheld.
- Timecode alignment error \<= 0.5 sec in single-camera footage and \<= 1 sec for synced multi-camera.
- 100% narrated claims traceable to source timestamps; zero invented goals, passes, or puck locations.
- Expert agreement on tactical interpretation: measure per-event; target >= 80% before unattended delivery, with disagreement review.
- No release if footage permission unclear or a critical identity error is found.

## Failure handling

No puck visible: discuss positioning only, not puck control. No calibrated ice: draw approximate screen-space arrows labeled illustrative. Too many occlusions: ask for GoPro second angle or human-selected shifts. Incomplete video: mark coverage; never call it a full-game review. Unclear tactics: 'possible alternative' not definitive correction. Insufficient valid clips: deliver fewer than ten.

## Architecture options

A: Work-mode repeatable job, manually invoked in chat; runtime tools need confirmation and testing. B: private backend job launched by chat agent, with Drive folder watcher only if desired. No UI app in either option. Notion stores specs; does not execute video processing.

## Pilot

5–10 minute single GoPro segment → identify player manually once → 10–20 candidate events → 3 expert-approved telestrated clips → full 10-clip review → full match. Benchmark against manually labeled identity, puck visibility, timecodes and coach judgements. Record runtime, costs and failure cases per stage.
